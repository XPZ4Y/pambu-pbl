WEEK 4: DEADLOCKS

Operating Systems | Simulation Using C Programming

1. Introduction to Deadlocks

A deadlock is a situation in an operating system where two or more processes wait indefinitely for resources held by each other. As a result, none of the processes can continue execution.

Deadlocks commonly occur when multiple processes compete for limited resources such as memory, files, printers, or locks.

2. Example of a Deadlock

Process P1: Holds Resource R1 and waits for R2.

Process P2: Holds Resource R2 and waits for R1.

Both processes wait for resources held by each other. Neither can proceed, resulting in a deadlock.

Resource allocation can be represented as follows:

P1 holds R1  →  P1 requests R2
P2 holds R2  →  P2 requests R1

P1 waits for P2
P2 waits for P1

Result: DEADLOCK

3. Four Necessary Conditions for Deadlock

1. Mutual Exclusion

Only one process can use a particular resource at a time.

2. Hold and Wait

A process holds one resource while waiting to acquire another resource.

3. No Preemption

A resource cannot be forcibly taken away from a process. It must be released voluntarily.

4. Circular Wait

A circular chain of processes exists in which each process waits for a resource held by the next process.

A deadlock requires all four conditions to exist simultaneously. Preventing any one of them can prevent this type of deadlock.

4. Simulation of Deadlock Using C

Deadlock can be simulated in C using threads and mutex locks. Threads represent processes, and mutex locks represent shared resources.

  • P1 locks R1 and then requests R2.
  • P2 locks R2 and then requests R1.
  • Both threads become blocked while waiting for each other.

5. C Program to Simulate Deadlock

File name: deadlock.c

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

pthread_mutex_t R1 = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t R2 = PTHREAD_MUTEX_INITIALIZER;

void *process1(void *arg)
{
    pthread_mutex_lock(&R1);
    printf("Process P1 acquired Resource R1\n");
    fflush(stdout);

    sleep(1);

    printf("Process P1 waiting for Resource R2\n");
    fflush(stdout);

    pthread_mutex_lock(&R2);

    printf("Process P1 acquired Resource R2\n");

    pthread_mutex_unlock(&R2);
    pthread_mutex_unlock(&R1);

    return NULL;
}

void *process2(void *arg)
{
    pthread_mutex_lock(&R2);
    printf("Process P2 acquired Resource R2\n");
    fflush(stdout);

    sleep(1);

    printf("Process P2 waiting for Resource R1\n");
    fflush(stdout);

    pthread_mutex_lock(&R1);

    printf("Process P2 acquired Resource R1\n");

    pthread_mutex_unlock(&R1);
    pthread_mutex_unlock(&R2);

    return NULL;
}

int main(void)
{
    pthread_t P1, P2;

    pthread_create(&P1, NULL, process1, NULL);
    pthread_create(&P2, NULL, process2, NULL);

    pthread_join(P1, NULL);
    pthread_join(P2, NULL);

    pthread_mutex_destroy(&R1);
    pthread_mutex_destroy(&R2);

    return 0;
}
Important: This program intentionally creates a deadlock and may hang indefinitely. Press Ctrl + C in the terminal to stop it. The mutexes must not be destroyed while the threads are blocked.

6. Compilation and Execution in VS Code

Save the C program as deadlock.c.

Step 1: Compile the program

gcc deadlock.c -o deadlock -pthread

Step 2: Execute the program

./deadlock

These commands work in a Linux terminal or WSL terminal with GCC and pthread support installed.

7. Sample Output

Process P1 acquired Resource R1
Process P2 acquired Resource R2
Process P1 waiting for Resource R2
Process P2 waiting for Resource R1

The order of the first messages may vary because thread scheduling is controlled by the operating system. After these messages, both threads wait indefinitely, demonstrating a deadlock.

8. Explanation of Important Functions

Function Purpose
pthread_create() Creates a new thread representing a process.
pthread_mutex_lock() Acquires a resource or waits until it becomes available.
sleep(1) Pauses a thread briefly to help demonstrate the deadlock.
pthread_join() Waits for a thread to finish execution.
pthread_mutex_unlock() Releases a resource.
pthread_mutex_destroy() Destroys a mutex after it is no longer in use.

9. Conclusion

Deadlock is an important operating system problem in which processes wait indefinitely for resources held by one another. Using threads and mutex locks in C, we can simulate a deadlock and understand how resource allocation can block processes.

This simulation demonstrates why operating systems need deadlock prevention, avoidance, and detection techniques to manage resources efficiently.
